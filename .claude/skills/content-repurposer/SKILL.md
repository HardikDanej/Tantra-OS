# Content Repurposer

One source, N native pieces — never the source poured into a different container. A blog post copy-pasted into LinkedIn is not repurposed, it's mis-shipped. Most "cross-posting" fails because the brand pretends adaptation happened when only the file got resized or the text got trimmed.

This skill has two tracks from the same source-inventory step: **social platform variants** (LinkedIn, X, Instagram, TikTok/Reels/Shorts, YouTube, Pinterest — where the sharper per-platform mechanics below apply) and **other derivatives** (email, slide deck, quote graphic, derivative blog post — lighter-weight formats that don't need the full variant-job apparatus). A single repurposing project can draw from both tracks.

## When to use vs. when to refuse

| Use this skill when | Refuse when |
|---|---|
| A real source (article, podcast, video, talk, report, photo essay) exists or is described in detail | Source is "we did a video, can you cross-post" with no content given |
| Target platforms/formats are listed with genuine audience differentiation | "Post it everywhere" with no priority, or all targets share the same audience with no reason to differentiate |
| The user accepts that each destination gets a new, native piece | The user wants identical copy/caption across platforms — refuse outright, this is the failure mode the skill exists to prevent |
| Source is strong enough to justify the spread | Source is weak — repurposing multiplies weakness, it doesn't fix it |
| The job is multi-format repurposing | The job is single-platform caption writing only — route to caption-writer |
| Repurposing is honest re-shaping | User wants the same essay spun into 50 SEO articles — that's content farming, refuse |

## Refusal-first checks

1. **Source described concretely.** Length, format, hook, key beats, payoff, available assets (B-roll, stills, transcript, script), rights status (music/talent) if video or audio. Without a real source, refuse.
2. **Source quality honest.** A weak source (no real hook, no real payoff, no compelling angle) produces weak derivatives everywhere. Surface this rather than repurposing around it.
3. **Genuine audience differentiation across targets.** If every target platform's audience is the same in every way that matters, the work is resizing, not repurposing — say so.
4. **Time/production budget matches ambition.** Genuine per-platform adaptation takes time. An hour and five platforms means two done well beats five done badly — say which two.
5. **Rights cleared per destination.** Trending audio, licensed footage, or talent releases may not carry across platforms or formats. Confirm before building a variant that depends on them.
6. **Native-or-skip.** A destination where only a non-native version is achievable (a square video on a vertical-feed platform, a long thread on a platform that hides threads) is often better skipped than half-served. Say so explicitly as a skip recommendation, not a silent omission.

## Workflow

### Step 1: Source inventory (shared by both tracks)

Read, watch, or listen to the actual source. Identify:
- **Thesis** — the core claim, one line
- **Pillars / support beats** — 3–7 main supporting ideas, data points, or demo moments
- **Strongest hook moment** — the single most arresting frame, line, or claim
- **Payoff** — what the audience gets if they finish
- **Quotable phrases / quote-worthy lines**
- **Stories or examples** — narrative chunks that travel well on their own
- **Original CTA**, if any

### Step 2: Choose targets and assign each one a job

Not every source goes everywhere. Pick targets based on where the audience actually is and what the source's ideas play well in (a story-heavy piece works on LinkedIn; a data-heavy piece works as a chart-led carousel). For each target, assign a variant job — this is what actually differentiates a real adaptation from a resize:

- **Hook excerpt** — pulls one beat to drive viewers to the source (Reels/Shorts → YouTube long-form)
- **Standalone version** — reframed to be fully self-contained for that destination's audience
- **Companion piece** — lives alongside the source (a carousel summary of a video, a thread expansion of a podcast)
- **Discovery hook** — designed to put the source on a non-follower's radar, with a clear path back to it

### Step 3a: Social platform track — per-platform treatment

Common source-to-platform mismatches and the fix:
- **Long-form video → Reels/Shorts:** extract the strongest 30-second beat, rebuild a hook frame, add captions — never just clip "minute X to minute Y"
- **Long-form video → carousel:** 5–8 slides, each one beat, designed for save, not view
- **Podcast (audio) → video platforms:** pick a 60–90s argument, build a captioned video or audiogram with a rebuilt hook frame
- **Blog post → LinkedIn:** rewrite as a native post (first 2 lines as preview hook, scannable body rhythm) — never paste an excerpt with a link
- **Blog post → X thread:** rebuild from scratch; a thread is a sequence of standalone-tweet-worthy beats, not a chopped article
- **Photo essay → IG carousel vs. Pinterest pins vs. blog:** each demands different framing and copy

**Rebuild the hook per platform** — every platform has a different reading/watching pattern in the first 1–3 seconds or first 1–2 lines, and the source's hook rarely transfers verbatim. This is the single highest-leverage piece of adaptation work.

**Length by reading pattern** (starting positions, adjust by topic/audience): TikTok/Reels/Shorts 15–45s; YouTube long-form 8–20 min; LinkedIn 800–2,000 chars; X 280 chars or a thread that earns its length; IG carousel 5–10 slides; Pinterest short, keyword-aware descriptions.

**Localize tone, don't translate it:** LinkedIn — professional, concrete claims; X — sharp, conversational, aphorism-friendly; TikTok — native vernacular, less "branded"; IG — visual-first, emotional registers tolerated; Pinterest — keyword-aware, descriptive; YouTube — longer attention budget.

**CTA per platform, not one CTA everywhere:** Reels/Shorts → YouTube: "full breakdown on YouTube" + link in bio/pinned comment. X thread → blog: link at the end, after the thread earns the click. Carousel: the CTA is often "save this," not "go to source."

**Rights and asset checklist:** aspect ratio (9:16 for Reels/Shorts/TikTok, square/vertical for IG feed, horizontal for YouTube), captions burned-in or platform-native, thumbnail per platform, and confirm music/talent rights carry to the destination before building the variant around them.

### Step 3b: Other-format track — per-format treatment

- **Newsletter/email:** subject line tested separately from the source's title; hook above the fold; scannable subheads and short paragraphs; one CTA per email, don't dilute; sign-off in brand voice.
- **Slide deck:** 1–3 slides per major pillar, visual-led, built for reuse in sales/talk contexts.
- **Quote graphic:** a single line that lands without context, brand-styled, ends with attribution; square/portrait for IG, landscape for LinkedIn/X.
- **Derivative blog post:** a genuinely new angle or synthesis drawn from the source, not a rewording — if it would just restate the source, it doesn't belong on this track.

### Step 4: Avoid repurposing tells (both tracks)

- No "as I wrote in my recent article" pointing at the source — each derivative should stand on its own
- No identical hook reused across destinations
- No "read the full article" as the primary value prop — give value first, link as bonus
- No recap-of-the-source structure — a derivative is not a teaser for the source, it's its own piece

### Step 5: Sequence, don't dump

Release over 2–4 weeks, not all on day 1. A common pattern for a long-form anchor (e.g., a 20-minute podcast): Day 0 — source published; Day 0–2 — short-form hook excerpts routing to the source; Day 3–7 — companion pieces (thread, carousel, email); Day 7–14 — re-resurface the strongest variant, possibly remixed. Adjust to the source; this isn't universal.

### Step 6: Measurement

Track per destination: engagement (likes/comments/shares/saves), click-through where measurable, source attribution (do people find the source from this piece), and audience growth attributable to it. Multi-format reach is the union of all destinations minus overlap — it beats single-format on all but the most niche audiences.

## Anti-patterns

1. ❌ Same copy or caption pasted across every destination
2. ❌ Linking to the source as the primary value prop of every derivative
3. ❌ An AI-generated thread that's just the article cut into 280-char chunks — preserves AI cadence, each tweet should be its own thought
4. ❌ A carousel with full paragraphs per slide — fails the scroll-speed test
5. ❌ Reels/Shorts as a literal video reading of the article — wrong medium
6. ❌ Reuploading a horizontal video to a vertical-feed platform with letterboxing
7. ❌ Cropping a long video to 60s without rebuilding the hook
8. ❌ Same hook line across every variant — kills each platform's native register
9. ❌ Driving every destination's CTA to the same friction/destination regardless of context
10. ❌ Forcing a non-native form onto a platform where it underperforms instead of recommending a skip
11. ❌ Publishing everywhere simultaneously with no sequencing logic
12. ❌ Repurposing weak source content — multiplies the weakness, doesn't fix it
13. ❌ Missing attribution when a derivative lifts a founder's quote or a specific claim
14. ❌ Skipping measurement — no per-destination tracking means no way to tune the mix
15. ❌ Over-saturating — the same idea across seven destinations in three days reads as fatigue, not reach
16. ❌ Not clearing music/talent rights before building a variant around them

## Confidence calibration

**HIGH confidence:** format-mismatch mapping (which transformation a given source-to-destination pair needs), the variant-job framework, anti-pattern detection, sequencing patterns, aspect-ratio/rights pitfalls.

**MEDIUM confidence:** optimal length per variant (depends on source density and audience), tone calibration for a specific brand across destinations, whether a given source is "strong enough" to justify a given destination.

**LOW confidence:** predicting the performance of any single variant, niche-specific platform conventions without ground truth, trending-audio applicability (verify within days of posting — route to platform-algorithm-advisor if the platform mechanic itself is in question).

When confidence is LOW, the output is "test this variant," never "this will work."

## Stop conditions

- Source is weaker than the user thinks — surface it; repurposing will not fix it
- Rights status on a key asset is unclear — pause, route to the user or counsel
- Time budget can't support genuine adaptation across all requested targets — propose the highest-leverage subset instead
- A target demands a native form the user can't produce — recommend a skip, don't half-serve it
- Mid-project, the user asks to "just make it the same everywhere" — refuse; this is the exact outcome the skill exists to prevent
- A platform mechanic itself is uncertain or recently changed — route to platform-algorithm-advisor for current state before finalizing that destination's variant
